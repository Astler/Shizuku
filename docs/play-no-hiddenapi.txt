Implementation

- HiddenApiBypass 6.1 is githubImplementation only. Application startup calls a
  flavor-specific AppProcessApis: GitHub still exempts all hidden APIs on API 28+;
  Play initialization is a no-op.
- GitHub ShizukuSystemApis is moved unchanged, byte for byte, to src/github.
  Play uses primitive Parcel requests on the existing Shizuku binder, without
  SystemServiceBinder hooks, ServiceManager lookup, or hidden framework objects.
- Play keeps owner-only users, denied permission checks, empty package lists,
  and no-op permission mutations when the state machine says the server is down.
  It also clears its user cache in that case. RPC failures for package/permission
  operations remain errors; user enumeration failures return the owner fallback.
- User-list RPC sends ID/name pairs, never hidden UserInfo parcelables. Package
  lists use the existing ParcelableListSlice implementation to support large lists.
- Runtime permission RPC uses existing Android17Compat, preserving its Android 17
  device-ID/signature handling and the older compat version branches.
- ADB port discovery and MIUI tutorial detection use /system/bin/getprop under the
  app UID in Play, so they also work before the server starts. No su is requested.
- Pairing uses public SSLSockets.exportKeyingMaterial on Android 12+. On Android 11,
  a Play-only Bouncy Castle bctls-jdk18on:1.80 client provides mutual TLS 1.3 and the
  same 64-byte exporter with the existing "adb-label\0" label and null context.
  It uses the existing RSA key/certificate and SPAKE2 peer authentication. The BC
  version aligns with the existing bcpkix dependency; no provider is installed
  globally. GitHub retains its original platform Conscrypt pairing path.
- The manager Refine plugin is removed because manager code no longer uses alias
  casts. It also avoids rewriting signed BC jars in JVM tests. Server, starter,
  and server-shared still use their existing plugin/runtime configuration.
- Manager's direct compat and DeviceCompatibility dependencies are GitHub-only.
  Server/starter still pull compat transitively into both flavors. Compile-only
  hidden stubs remain available to R8 for linking the embedded server's types;
  the stubs are not packaged.
- Public AIDL, API version/patch version, rebrand identifiers, Android 17 helpers,
  manifests, and release obfuscation rules are unchanged. No library was copied,
  shaded, relocated, renamed, or newly obfuscated to avoid detection.

New private protocol extensions

Descriptor: moe.shizuku.server.IShizukuService, unchanged.
Every reply begins with the usual Binder exception header.

10002 getUsers
  Request: no arguments.
  Reply: count:int, then repeated (id:int, name:String).
10003 getInstalledPackages
  Request: flags:long, userId:int.
  Reply: ParcelableListSlice<PackageInfo>.
10004 checkRuntimePermission
  Request: packageName:String, permissionName:String, userId:int.
  Reply: PackageManager permission result:int.
10005 grantRuntimePermission
10006 revokeRuntimePermission
  Request: packageName:String, permissionName:String, userId:int.
  Reply: no payload after the exception header.

All five enforce the descriptor and existing manager UID/app-ID authorization
before reading arguments or clearing Binder identity. Identity is restored in a
finally block. No public transaction was changed or renumbered; 10001 remains
getApplications. api/aidl and all other API submodule files are unchanged. Clients
using dev.rikka.shizuku:api:13.1.5 retain the existing wire protocol.

Restart the bundled server after installing this manager update. An older/upstream
server will not implement 10002–10006; Play never falls back to app-process hidden
calls. Unknown transactions produce an explicit restart error, except user listing,
which retains its owner fallback. Compatibility with existing third-party clients
does not imply these new manager operations work with older servers.

Manager-process hidden API audit

Inspected manager main/play/github Kotlin and Java, JNI class lookups, manager
calls into shared modules, and the directly used Rikka compatibility helpers.

Original call sites and disposition:
1. ShizukuApplication companion init: HiddenApiBypass.setHiddenApiExemptions.
   GitHub-only AppProcessApis.initialize; absent from Play.
2. ShizukuSystemApis init: SystemServiceBinder's ServiceManager lookup/wrapper.
   GitHub-only; Play never initializes the listener or wraps hidden AIDL interfaces.
3. ShizukuSystemApis.getUsers: UserManagerApis/IUserManager and UserInfo fields.
   Play RPC 10002, primitive result only.
4. ShizukuSystemApis.getInstalledPackages: InstalledPackagesCompat reflection on
   ActivityThread, getInstalledPackagesAsUser, compat Services/IPackageManager,
   and framework ParceledListSlice/PackageInfoList return values.
   Play RPC 10003; reflection executes in the server.
5. ShizukuSystemApis.checkPermission/grantRuntimePermission/revokeRuntimePermission:
   PermissionManagerApis and hidden package/permission managers.
   Play RPCs 10004–10006, through Android17Compat in the server.
6. EnvironmentUtils.getAdbTcpPort: android.os.SystemProperties.getInt (two keys).
   Play uses getprop; GitHub retains the original property calls.
7. AdbPairingClient.setupTlsConnection: com.android.org.conscrypt.Conscrypt exporter.
   Play uses public platform TLS or the public BC TLS API as described above.
8. AdbPairingTutorialActivity and ShellTutorialActivity: DeviceCompatibility.isMiui
   indirectly called SystemProperties.get. Play uses getprop for the same property;
   GitHub retains DeviceCompatibility.

No additional manager source Refine calls, IPackageManager/IUserManager references,
or reflection on hidden Android classes were found. Compiled Play manager classes
also have no references to the audited hidden types; evidence is in
out/play-no-hiddenapi/manager-api-audit.txt. Rikka ResourceUtils/ClipboardUtils
use public Resources/ClipboardManager APIs in the inspected calls.
The API module's SystemServiceHelper reflection remains available as library code,
but the Play manager has no caller. Shared OsUtils.SELinux and the hidden APIs in
Service/UserService/ServiceStarter are server or app_process entry paths, not
manager app-process calls. The manager's use of server workerHandler uses only
public HandlerThread/Handler APIs. JNI lookups register this app's native classes.

Part B assessment and next implementation

Technically feasible with compileOnly hidden stubs and purpose-built server calls,
but not a contained dependency replacement. Current direct consumers comprise
10 production files: server/{BinderSender,ShizukuConfigManager,ShizukuService,
ShizukuUserServiceManager,util/Android17Compat,util/InstalledPackagesCompat},
api/server-shared/{Service,UserService,UserServiceManager}, and starter/ServiceStarter.
Three existing server test files also mock compat entry points. The change
crosses the API submodule and roughly four module/plugin dependency declarations.

Estimated follow-up: approximately 20–30 changed/new files, 700–1200 lines of
service/signature adapters, stubs and focused tests, about 2–4 engineering days
plus the Android device matrix. This is an estimate, not completed work.

The inspected published 4.4.0 sources contain behavior that must be preserved:
- Package APIs switch int flags to long flags on Android 13.
- Permission checks route via IPermissionManager on Android 11, back through
  IPackageManager on Android 12+, plus the existing Android 17 reflection fallback.
- Android 14 base/QPR2/QPR3 grant/revoke signatures differ: no device ID, int device
  ID, or persistent String ID; revocation also has reason/no-reason variants.
- User enumeration and information, activity launches across work profiles,
  process and UID observers, provider acquisition/release, and service lookup
  caching/death need explicit implementations, not dependency deletion.
- Observer signatures evolve (UID sequence/capability and process-start callbacks).
- UserService's ContextHidden/UserHandleHidden aliases require actual framework
  signatures via compile-only stubs or narrowly scoped server reflection. Casting
  to a fictitious alias class without Refine is invalid.
- minSdk remains 24: although the requested matrix is Android 11–17, the older
  ActivityManager/provider and observer branches cannot silently be discarded.
- Existing Android17Compat and InstalledPackagesCompat safeguards must survive.

Plan: introduce narrowly scoped, application-owned system-service entry points
using compileOnly stub types; adapt only the required operations and preserve
each version branch; implement observer subclasses; replace UserService aliases;
move tests from compat mocks to the new boundary; remove compat/Refine from server,
server-shared and starter together; verify both runtime dependency graphs and all
dex (including the rish asset). No copying a runtime library under another package.
